Portal Meter

Pay-per-request API settlement on Portaldot V3, across both of its VMs

connecting to PortaldotV3 testnet…

An API provider lists an endpoint with a price. A client pays for one request in an ERC-20 (here a Portaldot native asset, reached through the pallet-assets ERC-20 precompile). The payment waits in escrow in a Solidity contract on Portaldot's EVM. The provider settles it once it has served the request, or refunds it. An ink! registry on Portaldot's WASM VM keeps the provider's public record. Everything on this page is read live from the testnet by your browser.

1 GET → 402 quote
2 pay() on EVM
3 retry with signed proof
4 served once + receipt
5 settle + ink! record, one tx

That is the escrow path, for calls worth a few cents or more. High-frequency APIs use a prepaid session: one budget, a signed voucher per request, many requests settled in one transaction.

Buy a real API call from this page

No wallet, no install. A public test key in this page signs a voucher against a capped prepaid session, the hosted seller checks it and answers. Nothing goes on-chain per request: the seller settles many requests in one transaction, in Solidity and ink! together, and each batch carries a signature from the session key over the requests made and the responses received. Test tokens only.
